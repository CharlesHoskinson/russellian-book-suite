# AGENTS.md — russellian-book-suite

Conventions and operating guidance for autonomous coding agents (Codex, Claude Code, Copilot agent, others).

## What this repo is

A monorepo of Python 3.13 skills that compose into a non-fiction book pipeline:
`book-knowledge`, `russellian-style`, `book-compose`, `book-review`, `review-conductor`, `book-qa`, `book-thesis`.
Each skill ships its own pytest suite. RDF/SPARQL/SHACL via rdflib + pyshacl. LLM tooling is parameterized — production code accepts a `Callable[[str], str]` so tests pass stub responses.

For human-targeted context and design conventions, also read `CLAUDE.md` at repo root.

## Agent autonomy

Default to **read and analyse freely; do not push commits, open PRs, or modify files** without explicit instruction. When asked to implement a change, follow the TDD pattern: failing test first, minimal implementation, passing test, commit.

## Setup

Each skill has its own `.venv` in `skills/<skill>/.venv/`. In a fresh clone the venvs may be missing; junction-link them from the user's installed-skill copies (Windows) or run `python -m venv .venv && .venv/bin/pip install -e .[dev]` (POSIX).

If installing fresh:

```bash
cd skills/<skill>
python -m venv .venv
.venv/Scripts/pip install -e ".[dev]"     # Windows
.venv/bin/pip install -e ".[dev]"         # POSIX
```

Note: `book-qa` has no `pyproject.toml` and uses the system Python or any junctioned venv. The CI workflow installs `pyyaml` + `pytest` directly for that skill.

## Tests

Per-skill invocation:

```bash
cd skills/<skill>
.venv/Scripts/python.exe -m pytest tests/ -q          # Windows
.venv/bin/python -m pytest tests/ -q                  # POSIX
```

Run all suites:

```bash
for s in book-knowledge russellian-style book-compose book-review review-conductor book-qa book-thesis; do
  (cd skills/$s && .venv/Scripts/python.exe -m pytest tests/ -q --tb=no || echo "FAIL: $s")
done
```

## Out of scope for any review or analysis

Skip these unconditionally:

- `**/.venv/**`, `**/__pycache__/**`, `**/*.egg-info/**`, `**/.pytest_cache/**`
- `examples/*/book/releases/**` — generated book artifacts (PDFs, HTML, manifests)
- `examples/*/graph/reports/**` — generated SHACL / propagation reports
- `examples/*/claims/snapshots/**` — pre-propagation ledger snapshots
- `examples/*/qa/swarm-findings.json` and `examples/*/qa/defects.json` when generated by tooling — review the producer, not the output
- `**/test_*.py` data fixtures embedded in tests — they're intentionally narrow
- Anything matching `*-generated.py` or carrying a `// @generated` or `# generated` marker

Use `git ls-files` as the authoritative file list when enumerating sources. Never enumerate via `find` or directory walks — those see venv binaries and generated artifacts.

## Git and PR rules

Per the user's `~/.claude/CLAUDE.md` (which applies to this repo):

- **No Co-Authored-By lines** mentioning Claude, Codex, or any AI in any commit
- **No AI attribution** in commits, file contents, or code comments
- **No AI smells**: no "Main theorem:", "**Proof strategy:**", "key insight", numbered proof steps, excessive formatting
- **Terse, human-style commit messages**: imperative mood, ≤72 char subject, body only when the why isn't obvious
- **One problem per PR**: split unrelated changes into separate PRs
- **Never amend published commits**: prefer a new commit
- **Never push to main directly**: always via PR
- **Never use `--no-verify`** or skip hooks/signing unless explicitly instructed

## Known pitfalls

- **Append-only ledgers.** `claims/ledger.jsonl`, `claims/counter-claims.jsonl`, `claims/events.jsonl` are append-only. Use `book-knowledge/scripts/io_utils.py` (`read_jsonl`, `latest_per`) when reading them. Never use `open("w")` on a ledger file.
- **`WorkspaceLayout(root)` is the canonical workspace path abstraction.** There is no `for_root` classmethod despite older specs referencing it.
- **Cross-skill imports go through `sibling_skills.py`** in book-compose and book-review. E.g., `load_book_knowledge_module("io_utils")` aliases the namespace to avoid `scripts.*` collisions.
- **`proposed-transitions.jsonl` is overwritten on each `propose_writeback` run.** Consumers must process it before the next sentinel run. Documented in the script's docstring.
- **`BLOCKING_DEFEASIBLE = True`** is the default in `run_competency_queries.py`. Severity=critical defeasible fires hard-fail the QA gate; severity=important fires remain warnings.
