# Target CI design — russellian-book-suite

## Diagnosis (why main is red, and why it stays red)

Main is RED for a trivial reason wearing an infra disguise. The `nix preflight` job runs `nix develop -c make preflight`; `make preflight` runs `lint` first; `lint` runs `ruff check .` (Makefile:15) over the **whole tree**; ruff finds exactly two errors:

- `tools/readme-lint/tests/test_lint_readme.py:81` — F811, a duplicate `from scripts.lint_readme import parse_single_section` (already imported at line 7). Confirmed present on HEAD: line 81 re-imports the symbol from line 7.
- `tools/russellian-style-audit/scripts/health_check.py:215` — F841, `any_warn = True` assigned but never read (status at lines 228-233 is decided purely by `all_pass`/`any_fail`). The line-208 `any_warn = False` initialiser is also dead. Confirmed.

That `make` non-zero exit propagates through `preflight` into `ci required ✓` (the `if: always()` aggregator at ci.yml:236-253, which fails on `contains(needs.*.result,'failure')`).

The reason this keeps recurring (red continuously since PR #122) is **structural, not a one-off typo**, and the fix plan must address both layers:

1. **Lint is mis-scoped to the rust paths-filter.** ruff/clj-kondo/nixpkgs-fmt/cargo-fmt live only inside `preflight`, gated `if: github.event_name == 'push' || needs.changes.outputs.rust == 'true'` (ci.yml:144). The `rust` filter (ci.yml:37-46) does NOT match `**/*.py`. So a pure-Python PR **skips preflight entirely** — ruff never runs at PR time. The error only ever surfaces on the post-merge push to main (`event_name=='push'`). Every contributor sees green, merges, and turns main red. This is the engine of the perpetual red.
2. **The aggregator counts a skipped job as a pass.** `skipped` is neither `failure` nor `cancelled`, so `ci required ✓` goes green when preflight (and the invariant linters it carries) never ran. Combined with `required_approving_review_count: 0` in the ruleset, a PR can merge with zero human review AND zero lint/invariant execution.
3. **Pre-commit ruff only scans staged files** (`lefthook.yml:12` `ruff check {staged_files}`) while CI scans `.`. The two offending files were never staged in the PRs that touched them, so local hooks were green. The local gate and the required gate disagree on surface — by design, but with no authoritative whole-tree pass before push.

## Target design

### Principle: one always-run, cheap, fail-closed correctness gate; expensive jobs scoped by change.

**1. Hoist lint into its own always-run job (no `needs`, no rust gate).** Create a `lint` job in ci.yml that runs ruff + clj-kondo + nixpkgs-fmt + cargo-fmt + the NFR-4/NFR-5 invariant linters on **every** PR and push, on a plain (non-Nix or fast-Nix) runner. This single change closes the pure-Python-PR hole, the invariant-linters-never-gated hole, and the lint-suppresses-test-signal coupling at once. `preflight` keeps bake+regression+verifiers; lint leaves it.

**Resolving cost vs coverage:** lint is seconds, not the ~5min Nix cost. Running it always on every PR is cheap and is the highest-value signal. The *expensive* jobs (24-leg python matrix, cargo-test, Nix preflight) stay change-scoped — but scoped correctly: the paths-filter must gain `skills/**`, `tools/**`, `**/*.py`, and `**/*.clj*`/`**/*.edn`/`**/*.nix` so that skill and tooling changes actually trigger the jobs that test them. Today a skill-only PR skips both preflight and the invariant scan.

**2. Make `ci required ✓` fail-closed.** Replace the `contains(needs.*.result,'failure')` logic with an explicit per-need assertion: the always-run jobs (`lint`, `python-skill-matrix`) MUST be `success`; the change-scoped jobs (`preflight`, `cargo-test`) must be `success` **or** legitimately `skipped`. A bare `skipped` on an always-run job is a failure. This distinguishes "ran and passed" from "never ran."

**Resolving security vs convenience:** the recon shows `required_approving_review_count: 0`. Rather than block all automation, raise to **1 approval + `require_last_push_approval: true`**, and pair it with a scoped Dependabot auto-merge policy for patch-level bumps only. Human review returns for substantive PRs; routine patch bumps stay unattended but only after CI is green AND the auto-merge policy matches. The single-check-as-only-gate posture (one CI check, zero humans) is the supply-chain hole; 1 approval closes it without wedging the queue.

**3. Close the merge-queue trigger gap (CRITICAL, currently latent).** The ruleset enables a merge queue (`merge_queue` rule, ALLGREEN/SQUASH) whose required check is `ci required ✓`, but **ci.yml has no `merge_group:` trigger** (only `push`+`pull_request`). In the queue, ci.yml never runs, so `ci required ✓` never reports — the queue cannot satisfy its required check and wedges. Add `merge_group:` to ci.yml `on:`. This must land alongside or before any approval-count tightening, or the first queued merge stalls.

**4. Pin the required-check glyph and de-risk the rename.** `ci required ✓` (U+2713) must match byte-for-byte across ci.yml:237, ruleset-apply.sh:41, and branch-protection.md:11. Rename to ASCII `ci-required` in all three in one commit, and add a drift assertion (grep the job `name:` out of ci.yml, diff against the ruleset JSON) to the always-run lint job. Removes a silent merge-wedge foot-gun.

**5. Reproducibility hardening (staged, lower priority).** Per-skill pip installs are unpinned and cached on `pyproject.toml` only (setup-book-python:22-28) — non-deterministic resolution and a top supply-chain path across 24 legs. Target: per-skill `constraints.txt` (pip-compile), install `-c constraints.txt`, cache keyed on the lock. **Resolving speed vs reproducibility:** land skill-by-skill behind CI so a bad lock breaks one leg, not all 24. This is the largest-effort item and explicitly P2 — it does not block green and must not be rushed ahead of the correctness fixes.

**6. Reliability floor.** Add `timeout-minutes` to every job (~20-25 preflight, ~15 matrix/cargo legs, ~10 aggregators/changes, ~30 nightly Windows) at ~2x observed p99; pin `macos-latest`→`macos-15` and ci-legacy `ubuntu-latest`→`ubuntu-24.04` to stop silent OS/brew-z3 drift; wrap single-shot network steps (spaCy wheel, apt, brew, npm) in retry/backoff and cache the spaCy wheel by version. These are individually small and additive.

**7. Coverage gaps (additive, P2).** Add `scrapling-fetch` (highest supply-chain risk per dependabot.yml) and `syntopical-metabook` to the python matrix — at minimum an install+import smoke leg. Add `adsc-clinical` and `epidemiology` to cargo-test. Decide ci-legacy's fate: fold its unique coverage (py3.11/3.12 matrix, actionlint, z3/cljs smokes) into a scheduled nightly that actually runs, or delete it; the current self-trigger-only state is pure maintenance cost with zero signal. Move actionlint to an always-run PR job (it currently never validates ci.yml changes).

### Cross-persona tension ledger (explicit resolutions)

- **Cost vs coverage:** Cheap lint + invariants run *always*; expensive matrix/Nix/cargo run *change-scoped* with a correctly-widened filter (`skills/**`, `tools/**`, `**/*.py`, clj/nix globs) plus full-matrix on push-to-main. Per-skill matrix filtering (P2) cuts common-case spend without losing push coverage.
- **Speed vs reproducibility:** Pre-commit ruff stays staged-only (fast); add a pre-push whole-tree `ruff check .` so the authoritative pass runs before push. Lockfiles land incrementally (P2), not as a big-bang that could break all legs.
- **Security vs convenience:** 1 approval + last-push-approval restores human review; a narrow patch-only Dependabot auto-merge keeps routine bumps unattended. Drop the unused `pull-requests: write` from ci.yml (it runs untrusted fork code and never uses the scope; ci-budget.yml has its own grant). Pin the rust toolchain channel to match flake.nix 1.90.0.
- **Fail-fast vs signal:** `preflight` no longer carries lint, so a lint error can't suppress bake/regression/verifier signal; optionally run the residual chain with `make -k` for union-of-failures reporting.
