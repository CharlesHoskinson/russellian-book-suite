# Design: eval-onboarding-bench

## Harness shape

`skills/neurosym-forge/eval/onboarding-bench.py` is a single-file
script with three responsibilities:

1. Assemble the doc bundle (SKILL.md + SUPPORT_MATRIX.md +
   `docs/booklogic-dsl-reference.md` + every `references/**.md`).
2. For each `prompts/*.md`, invoke `run_agent(prompt, backend,
   workspace)` and capture milestones.
3. Write a CSV per invocation and exit non-zero if the regression gate
   trips.

Backends:

- `stub` — simulates an agent that succeeds in <100 ms. Used in CI to
  exercise the harness without an LLM.
- `claude-code` — placeholder; real subprocess wiring lands in a
  follow-up.
- `codex` — placeholder; same shape.

## Milestones captured per run

| Field                | Source                                  |
|----------------------|-----------------------------------------|
| `prompt`             | filename stem                           |
| `backend`            | CLI flag                                |
| `started_at`         | ISO 8601 UTC                            |
| `extract_passed_at`  | seconds since start when `make extract` passed |
| `ci_passed_at`       | seconds since start when `make ci` passed |
| `tool_calls`         | count of tool invocations               |
| `errors`             | count of agent-reported errors          |
| `outcome`            | `SUCCESS` / `TIMEOUT_extract` / `TIMEOUT_ci` / `FAILED_extract` / `FAILED_ci` / `TODO_real_backend_not_implemented` |
| `wall_time_seconds`  | wall clock                              |
| `doc_gaps`           | semicolon-joined list of paths grepped outside the doc bundle |

## Doc-gap detection

`detect_doc_gaps(agent_log_dir: Path) -> list[str]` scans the agent's
tool-call log (when present) for file paths that fall outside
`SKILL_ROOT / "references"`, `SKILL_ROOT / "SKILL.md"`,
`SKILL_ROOT / "SUPPORT_MATRIX.md"`, and `docs/booklogic-dsl-reference.md`.
For the stub backend the log is empty, so this returns `[]`.

## Timeout

`subprocess.run(..., timeout=args.timeout_seconds)` with
`TimeoutExpired` → `outcome = "TIMEOUT_extract"` (or `_ci` depending on
which phase was running). Default 1800 s (30 min) per prompt.

## Aggregator

`aggregate_runs.py` reads every `*.csv` under `skills/neurosym-forge/
eval/runs/` (configurable via `--runs-dir`), computes:

- `reach_extract_pct` = rows where `extract_passed_at != ""` /
  total rows
- `reach_ci_pct` = rows where `outcome == "SUCCESS"` / total rows
- `top_doc_gaps` = the five most frequent `doc_gaps` entries
- `top_framework_gaps` = the five most frequent `outcome != SUCCESS`
  failure modes

Output: `docs/eval/onboarding-bench-report.md`.

## Regression gate

When `--backend != stub` and `reach_ci_pct < 0.80`, the harness exits
1 and CI fails. Stub runs always pass the gate by construction (the
stub is deterministically successful).

## Weekly CI

`.github/workflows/onboarding-bench.yml` runs on
`cron: '0 6 * * 1'` (Mondays 06:00 UTC) and on `workflow_dispatch`.
It invokes the stub backend, runs the aggregator, and uploads the
report as an artifact. Real-backend wiring will require credentials
and a different workflow; out of scope here.

## File layout

```
skills/neurosym-forge/eval/
├── onboarding-bench.py
├── aggregate_runs.py
├── prompts/
│   ├── temperature-bounded-reaction.md
│   ├── parishes-aggregation.md
│   └── string-binomial-match.md
└── runs/                  (gitignored — populated at runtime)

docs/eval/
└── onboarding-bench-report.md   (regenerated by aggregator)

.github/workflows/
└── onboarding-bench.yml

skills/neurosym-forge/tests/
└── test_onboarding_bench.py
```
