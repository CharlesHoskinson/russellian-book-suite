# Design: tier1-binding-schema

## Canonical var-name function

The Z3 variable name for a predicate-subject pair is the single most
load-bearing string in the framework. Today three independent
reconstructions exist:

```
CLJS booklogic.cljs:  (str (name pred) "_" (name subj))
Python codegen:       f"{head.name}_{sub_str.lstrip('?')}"
Rust smt.rs:          format!("{}_{}", pred.trim_start_matches(':'),
                                       subj.trim_start_matches(':'))
```

All three differ in edge-case handling (CLJS doesn't strip `?`, Python
strips colon only off subject, Rust strips colon off both, etc.). The
fix is a single canonical algorithm:

```
canonical_var_name(predicate: string, subject: string) -> string
  pred = predicate after stripping leading ':' or '?'
  subj = subject  after stripping leading ':' or '?'
  return pred + '_' + subj
```

Implemented in each language under the SAME name. Round-trip test
file at `tests/golden/canonical_var_name.edn`:

```edn
[{:predicate :osmotic-pressure-pa :subject :s        :want "osmotic-pressure-pa_s"}
 {:predicate ":osmotic-pressure-pa" :subject ":s"    :want "osmotic-pressure-pa_s"}
 {:predicate "?osmotic-pressure-pa" :subject "?s"    :want "osmotic-pressure-pa_s"}
 {:predicate :vant-hoff-i :subject :Bermuda          :want "vant-hoff-i_Bermuda"}]
```

Each language's test reads the golden file and asserts
`canonical_var_name(:predicate, :subject) == :want` for every row.

## Schema file

Generated by `nbb -m <slug>.booklogic .` from `defsort` + `defpredicate`:

```edn
;; rules/booklogic-schema.edn — GENERATED, do not edit by hand
{:version 1
 :sorts {:solution {:kind :primitive}
         :real     {:kind :primitive}}
 :predicates
  {:osmotic-pressure-pa {:arg-sorts [:solution] :return :real}
   :vant-hoff-i         {:arg-sorts [:solution] :return :real}
   :molarity            {:arg-sorts [:solution] :return :real}
   :temperature-k       {:arg-sorts [:solution] :return :real}}}
```

The CLJS validator already does sort+predicate validation; the
generator just persists the result. Python ingest reads this schema
to validate predicate names before emitting atoms (catches typos like
`:Osmotic-Pressure` early). Rust reads it to validate atom shape at
runtime (a `Real::new_const` for a predicate not declared as `:return :real`
is now a flagged error, not a free variable).

## Stop-gaps (from EDN audit)

### 1. `ingest_ledger.py` keyword emission

Today:
```python
pred = f":{pred_raw.name}" if isinstance(pred_raw, Keyword) else str(pred_raw)
```

Tomorrow:
```python
pred = pred_raw if isinstance(pred_raw, Keyword) else Keyword(str(pred_raw).lstrip(":"))
```

The atom dict now carries a Python `Keyword` object, and `_edn_writer.py`
serialises it as `:foo`, parsed by edn-rs as `Edn::Key("foo")`.

### 2. `_edn_writer.py` float emission

Today: `repr(f)` produces `1.5e-10`, unreadable by edn-rs 0.19.

Tomorrow:
```python
def _emit_float(f: float) -> str:
    if not isfinite(f):
        raise ValueError(...)
    s = f"{f:.17g}"
    if "e" in s.lower():
        s = f"{f:.20f}".rstrip("0").rstrip(".") or "0.0"
    return s
```

`{f:.17g}` is sufficient for IEEE 754 double-precision round-trip. If
that triggers scientific notation, the fallback expands to fixed-point.

### 3. List vs vector distinguishability

Today: `_edn_reader.py` reads both `(...)` and `[...]` as Python `list`;
`_edn_writer.py` emits `[...]` always. CLJS consumers using
`(list? form)` (meander pattern dispatch) silently break on round-trip.

Tomorrow: a thin dataclass split:
```python
@dataclass
class EdnList:    items: list
@dataclass
class EdnVector:  items: list
```

Reader emits `EdnList` for `(...)`, `EdnVector` for `[...]`. Writer
emits `(...)` for `EdnList`, `[...]` for `EdnVector`. Legacy
`isinstance(x, list)` checks become `isinstance(x, (EdnList, EdnVector))`.

## Golden test files

`tests/golden/` ships 6 files covering the round-trip shapes:

```
canonical_var_name.edn — algorithm vectors (above)
expression_atom.edn    — :kind :expression with :predicate :subject :value
opaque_atom.edn        — :kind :symbol :name :OPAQUE
context_atom.edn       — :kind :symbol :name :CONTEXT
predicate_entry.edn    — entries from rules/predicates.edn
verdict.edn            — :status :sat / :unsat / :unknown shapes
constraint_entry.edn   — entries from rules/constraints.edn (approx= form)
```

Each comes with a pytest:
```python
@pytest.mark.parametrize("golden", GOLDEN_FILES)
def test_python_round_trip_byte_identical(golden):
    raw = golden.read_text(encoding="utf-8")
    assert write_edn_str(read_edn_str(raw)) == raw
```

And a Rust integration test that parses each golden file:
```rust
#[test]
fn golden_files_parse_with_expected_variants() {
    for path in GOLDEN_PATHS {
        let edn: Edn = std::fs::read_to_string(path)?.parse()?;
        // assert atom["kind"] is Edn::Key, atom["value"] is Edn::Double, etc.
    }
}
```

## Why not jump to Tier 4 (full schema-as-types)?

Tier 4 would replace EDN entirely with a typed IR (protobuf, capnp,
or a Rust-defined IDL with codegen for the three languages). That is
correct architecture but a multi-PR rewrite. Tier 1's binding-schema
+ canonical-name + golden tests + stop-gaps closes ~80 % of the leak
surface for the cost of ~3 days, leaving the path to Tier 4 open.
