# Change: tier1-binding-schema

**Tier:** 1 of 4 (the structural fix for cross-language drift)
**Branch:** `feat/tier1-binding-schema`
**Depends on:** none (independent of A and B)

## Why

Six of the seven recent silent-failure incidents (CLJS namespace dash
vs. underscore, `(?P<v>)` vs. `(?<v>)`, `:sol` vs. `?s`, `:value 1` vs.
`:value 1.0`, EDN keyword-vs-string colon prefix, ingest float
scientific-notation fallthrough) trace to the same architectural
property: **the framework is a string-passing pipeline with three
languages independently reconstructing the same logical identifier.**
The CLJS compiler generates `(:foo ?s)`, the Python ingester emits
`{:predicate ":foo" :subject ":s"}`, and the Rust verifier rebuilds
`format!("{}_{}", ...)`. Nothing forces the three to agree. Every
cross-language convention is documented in prose and enforced only by
runtime failure.

The next domain author writing a new verifier will hit this class of
bug again, because there is no central declaration of "the canonical
Z3 variable name for predicate P at subject S".

## What

- A single canonical function — `canonical_var_name(predicate, subject)` —
  implemented in CLJS (`canonical-var-name`), Python
  (`canonical_var_name`), and Rust (`canonical_var_name`), each
  producing byte-identical strings for the same `(predicate, subject)`
  input.
- A schema file `rules/booklogic-schema.edn` per project, GENERATED by
  `nbb -m <slug>.booklogic .` from the existing `defsort` + `defpredicate`
  forms, enumerating every predicate name + arg-sorts + return-sort +
  expected subject-placeholder.
- Golden EDN test files at `skills/neurosym-forge/tests/golden/*.edn`
  covering the atom, predicate-entry, verdict, and constraint shapes.
  Pytest asserts byte-identical Python round-trip; a Rust `#[test]`
  asserts edn-rs parses each file with the expected `Edn::*` variants.
- The three Tier 1 tactical stop-gaps from the EDN audit:
  - Python `ingest_ledger.py` emits `Keyword` objects, not f-strings,
    for `:predicate` and `:subject`.
  - Python `_edn_writer.py` emits floats via a non-scientific-notation
    formatter (`f"{v:.17g}"` with a re-parse guard).
  - Python `_edn_reader.py` distinguishes `EdnList` (read from `(...)`)
    from `EdnVector` (read from `[...]`) and the writer preserves the
    distinction on round-trip.

## Capabilities touched

## Acceptance

- A regression test mutates the CLJS canonical-var-name implementation
  and the Python golden round-trip test catches the drift.
- `_edn_writer.py` never emits scientific-notation floats for any value
  in the f64 range.
- An EDN atom written by Python and read by Rust produces matching
  `Edn::Key` (not `Edn::Str`) for keyword fields.
